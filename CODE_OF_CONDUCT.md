# Code of Conduct

## Our standard

This project exists to help people defend systems they are responsible for.
Everyone involved — maintainers, contributors, and people asking questions — is
expected to behave with the ordinary professional courtesy you would extend to a
colleague.

Expected:

- Be direct about technical problems, and specific about evidence.
- Disagree about the work, not about the person doing it.
- Assume the other person is competent and acting in good faith.
- Accept that "I measured it and it does not hold" ends an argument.

Not accepted:

- Personal attacks, harassment, or discriminatory remarks of any kind.
- Publishing someone's private information.
- Sustained disruption of discussions or reviews.
- Encouraging or assisting unauthorised access to systems, or using this project
  to coordinate it.

## Security-specific expectations

This is a security project, so two additional rules apply:

- **Do not post working exploits or attack instructions** in issues or pull
  requests. Describe the class of problem; report specifics privately as
  `SECURITY.md` describes.
- **Do not post real captured data.** Logs, PCAPs, database extracts, and
  screenshots routinely contain addresses, hostnames, and user activity. Redact
  before sharing, or reproduce the problem with synthetic data.

## Scope

This applies in project spaces — the repository, issues, pull requests, and any
official discussion channel — and when representing the project elsewhere.

## Enforcement

Report unacceptable behaviour to the maintainers through the private channel in
`SECURITY.md`. Reports will be reviewed and handled in a way that respects the
reporter's privacy.

Maintainers may edit or remove contributions, and may bar people from
participation, when behaviour falls outside this document.
